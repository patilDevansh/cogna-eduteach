# MVP 2.0 — Pilot Plan

> MVP 2.0 exists to move from local demo to external learning pilot.

## Pilot Size

| Stage | Students | Duration | Goal |
|---|---:|---:|---|
| Internal dogfood | 3-5 | 3 days | reliability |
| Friendly pilot | 10-15 | 1 week | usability + reports |
| External pilot | 25-50 | 2-4 weeks | learning signal |

## Participant Profile

- Grade 8 CBSE or equivalent
- Currently learning linear equations
- Parent/guardian consent
- Uses app 3+ sessions per week

## Success Metrics

### Learning

- session completion rate >= 70%
- revision completion rate >= 60%
- misconception resolution rate tracked by category
- retention review success improves over first exposure
- independent correct rate trends upward for target concepts

### Product

- parent report viewed by >= 50% of active parents weekly
- student returns for second session >= 60%
- average session 8-15 minutes
- support issues logged and triaged

### Trust

- parent can explain what the app recommended
- reports include uncertainty when evidence is weak
- no student-facing diagnostic labels

## Pilot UX

Student:

1. Login with access code
2. Baseline or warm-up
3. Adaptive practice
4. Hints/explanations when needed
5. Revision queue
6. Short session summary

Parent:

1. Signup/login
2. Create/link student
3. View session summaries
4. Receive weekly report
5. See next recommended practice

## Privacy and Consent

- parent consent before practice
- no clinical diagnosis
- no raw answers to third-party analytics by default
- delete/export policy documented before external pilot
- content review complete before pilot

## Human Operations

Before launch:

- reviewer signs content checklist
- support contact defined
- incident owner defined
- pilot cohort spreadsheet or admin view prepared
- weekly report copy reviewed

During pilot:

- daily error check
- weekly content issue review
- parent feedback review
- decision fallback review

## Stop Conditions

Stop or pause pilot if:

- incorrect math reaches student
- parent can view wrong student data
- fallback decision rate exceeds threshold
- session flow repeatedly blocks students
- report language creates misleading claims

## Exit Criteria

MVP 2.0 succeeds if:

- product is used across multiple sessions
- reports are trusted by parents
- revision queue produces measurable follow-up practice
- diagnostics can explain decisions without manual DB inspection
- content pipeline can scale beyond one unit
